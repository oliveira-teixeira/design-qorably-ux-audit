UX Audit · New user point of view

Qorably, walked as a first‑time user

date 2026‑08‑25 env staging source QA_Tool_Maby · design branch method live walkthrough + code cross‑check

Verdict

The core loop is genuinely good. From a preset to five concrete, correctly tagged test cases took about ten seconds, and marking results feels instant. What holds the product back is everything around that loop: feedback that whispers when it should point, safety promises the backend only half keeps, an automation path that lets a new user run into a wall, and an accessibility baseline that is currently zero.

Priorities in one line each: give phones a way to navigate (H1), stop hard deleting test cases (H2), preflight the Run modal (H3), add the accessibility basics (H4), and fix Generate's validation story (M1).

What already works

  • The aha is real. Preset, Generate, five cases with happy path, negative, edge and validation tags, each with concrete steps ("photo.png, size 2MB"). The quality sells the tool by itself.
  • Result recording is tight. One click on Passed updates the row chip, the metrics tile, a status chip in the detail, and stamps Last tested. Nothing to learn.
  • The app takes you to your result. After generating, you land in the right suite automatically.
  • Storage earns trust. Deleted projects show the original suite, a 15 day countdown, and Restore. The empty states across suites, Storage and Export explain themselves.
  • History has attribution. Every create, run and delete is logged per person, in real time, searchable and filterable.
  • Helper copy is thoughtful. "Use CSS selector syntax, not HTML attribute syntax", "leave blank to keep existing", the script modal explaining both ways forward. Someone cared here.
  • Nice connected pattern. Dismissing the credentials reminder lights a red dot on Project Runners, so the nudge persists without nagging.
  • Long runs can be minimized, and sessions persist across reloads, so the two field login stays out of the way.

High severity

H1

Below 820px the app has no navigation at all

The only responsive rule for small screens is .sidebar{display:none}. No hamburger, no top bar links, no fallback. A QA opening a case on their phone, or anyone in a split window, is stranded on whichever screen loaded first.

Fix: a collapsible drawer behind a menu button, or honestly gate it: "Qorably needs a wider window" with a link to the guide. Half hiding is the worst of both.

index.html:794
H2

Case deletion is permanent while the product promises recoverability

The guide says "a wrong click is recoverable". True for projects, which soft delete into Storage. False for test cases: the endpoint runs DELETE FROM test_cases with no trash, and the same is true for Delete selection in bulk. The confirm dialog doesn't distinguish the two, so users learn the wrong safety model from projects and apply it to cases.

Fix: soft delete cases into Storage too, or say plainly in the confirm that cases are gone forever. An Undo toast would cover the single click slip.

routes.js:326 · index.html:2165
H3

Run automation lets a new user fail for minutes with no warning

The Run modal happily launches an entire project with zero generated scripts, no Base URL, and no runner credentials. Result: a multi minute wait, then raw Playwright output per case ("Protocol error (Page.navigate): Cannot navigate to invalid URL"). The cause and the fix, Base URL in Project Runners, are never named. Results also vanish when the modal closes; no run history survives anywhere visible.

Fix: preflight before enabling Run ("0 of 5 cases have scripts · Base URL not set → Configure runner"), translate the three common Playwright failures into human sentences, and persist the last run per project.

observed live · runner.js
H4

Accessibility baseline is zero

The app contains no heading elements, no aria attributes, no roles, three focus styles, and no autocomplete anywhere. Preset chips are divs with click handlers, invisible to keyboard and screen reader. Every modal stays mounted in the accessibility tree at all times. For an internal tool this may feel academic; for a tool whose job is quality, it is the first thing a QA minded user will notice.

Fix: real h1/h2 structure, button elements for chips, aria-hidden or display:none on closed modals, visible focus states, autocomplete="current-password" on login.

grep across index.html: 0 aria, 0 role, 0 h1–h3

Medium severity

M1

Generate validation misleads three different ways

The error renders its own markdown (** shows as text), it lists fields that are already filled (the message is a fixed string, not built from what is actually missing), and Environment is marked required with an asterisk but never validated, so projects generate with no environment. No field is ever highlighted and the page doesn't scroll to the problem.

Fix: build the message from the actually missing fields, mark those fields inline, and either validate Environment or drop its asterisk.

index.html:2246
M2

Switching presets silently destroys edited text

The guide tells users to "start from a preset, then adjust it". Adjust, click another preset out of curiosity, and the adjustments are gone with no confirm and no undo.

Fix: confirm before overwriting a description the user has touched, or keep an undo of the previous text.

verified live
M3

The credentials modal interrupts the product's best moment

2.5 seconds after your first generated cases appear, "PI PI PI" covers them. The instinct is right (credentials do gate quality) and the dot on Project Runners after "Maybe later" is a lovely touch, but the timing spends the aha moment. The new project also arrives collapsed with "--" metric tiles, so the payoff needs an extra click even after dismissing.

Fix: auto expand the newly generated project, and hold the reminder until the user has expanded or interacted, or demote it to a banner. Explain "--" tiles ("open a project to see metrics") or show zeros.

index.html:3700 · 2264
M4

The login gate is an overlay in front of a fully rendered app

The entire UI, all modals and the full guide ship in the DOM before authentication, behind a fixed overlay. API routes are properly session guarded, so data is safe, but the product surface, feature set and copy are readable by anyone, and authenticated users see the login flash on every load while the session check runs.

Fix: render the shell only after /auth/me resolves, and show a neutral loading state instead of the login flash.

auth.js · index.html:1672
M5

Runner credentials default to the Production tab

The environment tabs open on Production, so the path of least attention points credentials and first crawls at the live product.

Fix: default to Staging, or to the environment the project was generated for.

observed live
M6

No routing: one URL for everything, back button exits

Suites, projects and tools never change the URL. Nothing is linkable ("look at TC 03" can't travel in Slack), refresh loses your place, and browser back leaves the app.

Fix: hash routes are enough: #/regression/ux‑audit‑demo.

observed live
M7

The guide promises scripts that don't exist yet

"Each case carries a generated script behind the </> button" describes the ideal state, not the fresh project, where the modal is empty and the button reads Regenerate even though nothing was ever generated.

Fix: label it Generate script when none exists, and soften the guide's claim.

script modal, fresh project
M8

Identity is honor system and there is no way out

Login is any free text name plus one shared password, so History attribution is spoofable by design, and the UI has no logout control at all (the endpoint exists, unused). Fine tradeoffs for a small team, but they should be chosen, not accidental.

Fix: a logout item under the identity badge, and a short note in the guide about how identity works.

auth.js:9 · no logout in index.html
M9

History speaks in internals

A run logs as "design ran mode:by_project (5 cases)", leaking the enum and omitting which project was run. Entries also aren't clickable, so History is a dead end rather than a navigation surface.

Fix: "design ran UX Audit Demo, entire project, 5 cases", linked to the project.

Low severity

L1

Deletion UI undersells its own safety

Project delete hides behind a menu item called "Delete All" (all what?), then a native browser confirm that clashes with the styled UI and never mentions Storage. People hesitate before a safe action and breeze past a permanent one (H2).

Fix: rename to "Delete project…", use the app's own modal, and say "recoverable in Storage for 15 days".

index.html:2183
L2

Small copy and polish slips

The Generate form numbers skip from 09 to 11. "VER VIDEO" is Portuguese in an English UI, and runner session times format with the pt‑BR locale. "BeatifulAngie" drops an u. Metadata inputs truncate their own values at 1440px ("Desktop Pa", "Environmen"). Import documentation lives under a section titled Export.

Fix: sweep pass. Each is minutes; together they read as unfinished.

index.html:2371 et al.
L3

Login screen leaves new users guessing

"Your name or ID (e.g. Kiwi)" doesn't say the name is invented on the spot, and Team password has no "ask your lead" hint. The password field lacks autocomplete, so password managers won't reliably offer the shared secret.

Fix: one caption line under the form settles both, plus the autocomplete attribute.

index.html:808–812
L4

Empty states point but don't carry

"Go to Generate and create test cases for this suite" is plain text; the destination is a click away but not clickable. Dead code note: a light/dark theme toggle exists in the markup and is disabled with display:none !important.

Fix: make the empty state CTA a button; delete or ship the toggle.

Quick wins

Under an hour each, ordered by leverage:

  • Preflight the Run modal with script count and Base URL status, and point to Project Runners (defuses H3 without touching the runner).
  • Auto expand the project after generation and delay the PI PI PI reminder until after first interaction (M3).
  • Honest delete confirms: mention Storage on project delete, mention permanence on case delete (H2 stopgap, L1).
  • Validation message from actual missing fields, drop the literal asterisks, validate Environment or unmark it (M1).
  • Confirm before a preset overwrites edited text (M2).
  • Default runner tabs to Staging (M5).
  • Copy sweep: VER VIDEO, mode:by_project, Delete All, BeatifulAngie, 09→11 numbering (L2, M9).

Method and audit trail

Audited as a first time user on the staging environment (viewport 1440×900), then cross checked against the design branch of QA_Tool_Maby. During the session I generated one project, UX Audit Demo (Claude), marked one case Passed, ran its automation once, and deleted it. It now sits in Storage with 15 days left and can be restored or left to expire; the run, create and delete entries appear in History under "design". Mobile behavior was verified in source (the 820px rule) since the audit pane could not emulate a phone viewport reliably. The one thing I could not exercise end to end is a fully configured runner with credentials, which would be worth a follow up pass together with the crawl and Deep Analyse flows.
